# Этап 0 — БД-фундамент и миграция (реализовано)

Перевод системы с read-only Google-таблицы на Postgres с журналом платежей.
Схема — [db-schema.md](db-schema.md), ORM — `backend/models.py`.

## Что появилось в `backend/`

| Файл | Назначение |
|---|---|
| `db.py` | движок и сессия SQLAlchemy; `DATABASE_URL` (Postgres в проде, SQLite локально) |
| `models.py` | ORM-модели всех 9 таблиц + перечисления (см. db-schema.md) |
| `xlsx_reader.py` | чтение локального .xlsx в формат `(rows, formulas, tz)` парсера |
| `migration/extract.py` | гранулярная выгрузка (водитель × месяц) с дневными платежами |
| `migration/reconcile.py` | сверка выгрузки против строк листа «Итого»/«Осталось» |
| `migration/load.py` | идемпотентная загрузка в БД (резолв машин, upsert) |
| `migrate_sheet.py` | CLI-оркестратор: read → extract → reconcile → load |
| `alembic/`, `alembic.ini` | миграции схемы (baseline = все таблицы этапа 0) |

## Как запускать

```bash
cd backend
pip install -r requirements.txt

# 1) Создать схему (Postgres в проде; для теста по умолчанию sqlite:///./vtbfl.db)
export DATABASE_URL="postgresql+psycopg2://user:pass@host:5432/vtbfl"
alembic upgrade head

# 2) Сверка без записи (безопасно гонять многократно)
python migrate_sheet.py --xlsx "/path/Платежи клиентов 2026.xlsx"
#   или из живой Google-таблицы (нужен service-account, как у дашборда):
python migrate_sheet.py --google

# 3) Загрузка в БД (только при нуле расхождений; иначе отменяется)
python migrate_sheet.py --xlsx "/path/Платежи клиентов 2026.xlsx" --load
```

Флаги: `--load` — записать в БД; `--create-all` — создать таблицы через metadata
вместо alembic (быстрый локальный тест); `--force` — грузить вопреки расхождениям.

## Принципы реализации

- **Сверка — «ворота».** Грузим в БД только при нуле расхождений. Сверяем по каждой
  записи: `Σ дневных платежей == «Итого»` и `обязательство + оплата == «Осталось»`.
- **Знак.** В листе обязательство отрицательное; в БД храним положительным,
  знак долга несёт `balance = Σ payments − obligation` (отрицательный = долг).
- **Идемпотентность.** Upsert по натуральным ключам (имя/номер/период). Платежи
  миграции помечены пользователем `migration`; повторный прогон переписывает их и
  не трогает введённые оператором (другой `entered_by`).
- **Резолв машины.** Номер есть не во всех месяцах — переносим вперёд/назад; нет
  вовсе — плейсхолдер «Б/Н {имя}»; мусор («0.0») игнорируем.
- **Аномалии.** Текст вместо числа в дневной ячейке (напр. `'52 250'`) лист (SUM)
  не считает — мы тоже не считаем, но выводим оператору на исправление в источнике.
