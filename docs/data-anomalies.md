# Аномалии данных таблицы — чек-лист исправлений

Список «оплошностей оператора»: значения, которые **должны быть числом и учтены**,
но в листе введены так, что формула их не посчитала. Найдены аудитором
`backend/migration/audit.py` (полный сквозной скан всех месяцев и колонок).

Каждую строку нужно **исправить в источнике** (ввести числом). До исправления
миграция учитывает их через реестр `backend/migration/corrections.py`
(самоотключается, когда ячейка в листе станет числом — без двойного счёта).

## Открытые аномалии

| Ячейка | Период | Водитель | В листе | Должно быть | Тип | Влияние | Статус |
|---|---|---|---|---|---|---|---|
| `AW34` | 2026-01 | Каменский | текст `'52 250'` | `52250` | текст-в-платеже | оплата за 28.01 не учтена; Итого=0, Осталось=−52500 (полный долг вместо −250) | учитывается через corrections.py |

**Итого открытых: 1.** Аудитор не нашёл других подобных мест во всём листе
(ни текста-в-платеже, ни в обязательстве/Итого/Осталось/ставке, ни отрицательных
платежей).

## Как исправить в источнике

1. Открыть Google-таблицу, ячейка `AW34`.
2. Заменить текст `52 250` на число `52250` (без пробела/апострофа).
3. Формула `Итого`/`Осталось` пересчитает автоматически.
4. После исправления убрать запись из `corrections.py` (или оставить — она
   самоотключится, так как аномалии в листе больше не будет).

## Как проверять новые аномалии

```bash
cd backend
python migrate_sheet.py --xlsx "/path/Платежи клиентов 2026.xlsx"   # печатает все аномалии
```

При пробном прогоне (без `--load`) выводится список аномалий с пометкой, какие
из них будут учтены исправлением, а какие — нет (нужно внести в `corrections.py`
или поправить источник).
